Lesson 0001 · Ship safely

Why this bot needs three processes

One win: when you read AI-generated webhook code, you can tell whether slow work is in the right process — and which Compose services must be up.

The shipping risk

An inbound message can take seconds: CRM lookup, Gemini, dealer geocode, dispose, WhatsApp send. If that all happened inside the HTTP handler, the caller (JAM) would time out, retry, and you would get duplicate leads or silent drops. This repo’s answer: accept fast, work later.

1
client-webhook — validate, dedupe, enqueue, return 202. File: client_webhook.py.
2
redis — holds the RQ job (and sessions, rate limits, locks). Hostname inside Compose: redis.
3
client-worker — RQ worker runs client_tasks.handle_client_message (LLM, CRM, dispose, reply).

What Redis is here

Redis is an in-memory data structure store — fast key/value with TTLs, counters, locks. In this bot it is both the job broker for RQ and the place for short-lived ops state (seen message ids, rate limits, sessions). It is not your CRM and not Gemini. Source: What is Redis?

What Compose is doing

compose.yaml declares those three as separate services (containers). On Compose’s default network, the webhook reaches Redis at redis://redis:6379 because the service name is the DNS name. Source: Networking in Compose 

client-webhook  →  REDIS_URL=redis://redis:6379  →  enqueue job
client-worker   →  same REDIS_URL + CLIENT_QUEUE_NAME  →  run job
If webhook and worker disagree on CLIENT_QUEUE_NAME, jobs enqueue into a queue nobody listens to. Symptoms look like “bot accepts but never replies.” That is a deploy/config bug, not an LLM bug.

What RQ adds

RQ stores a pointer to a Python callable + arguments in Redis. The webhook enqueues client_tasks.handle_client_message; the worker process pops and executes it — with retries configured on enqueue. Source: RQ docs

Practice (retrieve, don’t re-read)

1. Why return 202 before the customer gets a reply?

2. Why does redis://redis:6379 work inside Compose?

3. Who runs handle_client_message?

Do this in the repo (2 minutes)

  1. Open compose.yaml and find client-webhook, client-worker, and redis.
  2. Confirm both app services set REDIS_URL: redis://redis:6379.
  3. In client_webhook.py, find RqEventPublisher.publish — note the string it enqueues.
  4. In client_worker.py, see that it starts rq worker on CLIENT_QUEUE_NAME.
